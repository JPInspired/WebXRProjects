Testing the Lessons

Before using a lesson with a class, try it once on a headset. This page walks you through it: what to check, how to read the frame rate, and how to send back anything that needs fixing. Your ticks and notes are kept on this device, so you can stop and come back.

1. Before You Start

  1. Charge the headset and update it if it asks.
  2. Do Space Setup (Quest settings → Physical space → Space setup) in the room you will teach in: shared sessions in the same room line up from it.
  3. Use the school Wi-Fi that the class will use, so you test what the students will get.
  4. Run the Network Check once on that Wi-Fi, ideally with two headsets, before the first shared lesson.
  5. Open this page in the headset’s browser (or open the lessons page and choose Testing Checklist).

2. Checking the Frame Rate

Every Open link below adds ?fps to the lesson’s address: a small counter appears in the bottom-left of your view. Look around the whole lesson for about 10 seconds.

Green numberThe headset is keeping up: the lesson will feel smooth.
Orange numberIt is not keeping up. Note the number in the lesson’s notes.
“lighter effects 1” or “2”The lesson switched off some of its effects by itself to stay smooth. Note it: it will still work.
For a whole classIn a shared session, the teacher can choose Teacher menu → Students → Effects → Light to give every headset the lighter look from the start.

3. Each Lesson

Start with the ones marked check first: they have the most detail. For each lesson, tick what works and write anything odd in its notes.

4. A Class Session (Two Headsets)

  1. Run the Network Check on both headsets first, including Check Two Headsets Together.
  2. On one headset, open a lesson and choose Start a Shared Session, ticking We are in the same room. Note the four-character code.
  3. On the second headset, type the code and a name into Joining a Class? at the top of the lessons page and choose Join the Class. It should open the same lesson within about 15 seconds.
  4. Check that both see each other in the list, that the second headset’s lab lines up with the room, and that the teacher’s choice of activity reaches the student.
  5. Try Teacher menu → Students → Effects → Light and back to Full: the student’s look should change within a few seconds.
  6. In Teacher menu → Class, try Pause the Class (the student’s view dims and their controls stop), Look Here (an arrow and a ring point the student towards the teacher) and a one-minute Timer (it counts down on both and chimes at the end).
  7. Let the student’s headset sleep for about 30 seconds, then wake it: it should say “reconnecting” and return to the session with its work.

5. Using Bare Hands

  1. Put the controllers down. A small ring appears between thumb and index finger: it closes as you pinch and turns green while holding something.
  2. Touch a menu button with a fingertip: it lights up as the finger comes close and presses once.
  3. Close a hand round a model to pick it up, and open it to let go. Held things should move smoothly.
  4. Turn a palm towards your face: two round buttons appear. With the other hand, Menus hides or shows the panels, and Move lets the next pinch-and-hold on empty space move the whole lab.

6. Sending Your Results

  1. Press Copy results above: it copies every lesson’s ticks and notes as plain text.
  2. Paste it into an email or a chat message to whoever looks after the WebXR Library.
  3. For a problem, the most useful things to include are: which lesson, what you did just before, what you expected and what happened, and the frame-rate number if it was orange. A photo of the headset view helps too.
